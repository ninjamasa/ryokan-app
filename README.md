# 旅館サイボーグ — トータルサポートアプリ (プロトタイプ)

旅館全体を **デジタルツイン化** し、館内をリアルタイムに可視化・運用支援するプロトタイプです。
半透明の3D建物の中を、従業員・お客様・注文といった「情報」が行き交います。

## できること

- **半透明3Dの館内全体像**（2階建て・客室6室＋厨房/食事処/大浴場/フロント）を自由に回転・ズーム
- **従業員の可視化** — 位置・現在のタスク・この先のタスク計画（予定）が見える。役割ごとに色分け（調理/配膳/フロント/清掃）
- **お客様のざっくりした状況** — 食事中 / くつろぎ中 / 入浴中 / 就寝中 / 外出中 など
- **ドリンク注文フロー** — 客室のボタンを押すと、注文オブジェクトが空間を飛んで **厨房へ瞬時に流れ**、タスクが溜まる。調理完了後は **配膳係が客室まで運び**、到着するとタスクが消化される
- **クリックでフォーカス** — 3D内の部屋・スタッフ・お客様をクリックすると、関連する関心事（タスク進捗・滞在状況・満足度など）が右パネルに表示される
- **リアルタイム・タスクボード** — 厨房 / 配膳 / 完了 のキューが溜まり・消化される様子を一覧。スタッフ操作で手動でも前に進められる
- **マルチクライアント同期** — SSE により、複数のブラウザ（客室タブレット・厨房ディスプレイ・配膳ディスプレイ）が同じ状態をリアルタイム共有

## 技術スタック

- **Next.js 15 (App Router)** — フロントエンドとバックエンド（API Routes）を一体で記述
- **React 19**
- **three.js + @react-three/fiber + @react-three/drei** — WebGLによる3D表現
- **zustand** — クライアント状態管理
- **Server-Sent Events (SSE)** — サーバー権威の状態をリアルタイム配信
- **TypeScript**

## アーキテクチャ

```
ブラウザ (3Dシーン + UI)
   │  ① 注文/操作 (POST /api/orders, PATCH /api/orders/:id)
   ▼
Next.js API Routes ──► サーバー側シミュレーション (src/lib/simulation.ts)
   ▲                      ・従業員の移動 / タスク計画
   │  ② 状態配信           ・お客様の行動
   └── SSE (/api/stream) ◄─ ・注文のライフサイクル(調理→配膳)
                            tick(400ms)ごとに状態を更新・全クライアントへ broadcast
```

「旅館の頭脳」である `simulation.ts` がプロセス内のインメモリ・ストアとして全状態を保持し、
一定間隔で時間を進めます。座標系（部屋・厨房・階段の位置）は `src/lib/layout.ts` に集約し、
3Dの描画とサーバーの移動ロジックが同じ空間を共有します。

### 注文のライフサイクル

```
placed(受付) → cooking(調理中) → ready(配膳待ち) → delivering(配膳中) → done(完了)
```

- 調理スタッフ・配膳スタッフが全員ふさがっていると、注文はそのフェーズで滞留します（= タスクが溜まる）。
- 配膳スタッフが客室へ到着すると自動でタスクが消化されます（タスクボードのボタンで手動進行も可）。

## ディレクトリ構成

```
src/
  app/
    layout.tsx, page.tsx, globals.css
    api/
      state/route.ts        # GET  現在のスナップショット
      stream/route.ts       # GET  SSE 配信
      orders/route.ts       # POST 注文作成
      orders/[id]/route.ts  # PATCH タスクを次フェーズへ
  lib/
    types.ts                # ドメイン型
    layout.ts               # 旅館の空間レイアウト(座標)
    simulation.ts           # サーバー側シミュレーション(シングルトン)
    client/
      store.ts              # zustand ストア + SSE接続
      visuals.ts            # 配色・ラベル
  components/
    Dashboard.tsx           # 全体の組み立て
    Scene.tsx               # R3F Canvas / カメラ / ライト
    Building.tsx            # 半透明シェル・床・クリック可能な部屋
    Markers.tsx             # 従業員・お客様マーカー(位置補間)
    OrderFlow.tsx           # 空間を流れる注文オブジェクト
    Hud.tsx                 # ヘッダー / KPI / 凡例
    FocusPanel.tsx          # クリック時の詳細パネル + 注文ボタン
    TaskBoard.tsx           # 厨房/配膳/完了 のタスクボード
```

## 開発

```bash
npm install
npm run dev      # http://localhost:3000
# 本番ビルド
npm run build && npm run start
```

> **同期のデモ**: ブラウザを2つ開いて、片方で客室のドリンクを注文すると、
> もう片方のタスクボードと3Dシーンにも即座に反映されます。

## プロトタイプの割り切り

- 状態はサーバープロセスのメモリ上に保持（単一プロセス前提）。永続化やサーバーレス分散は未対応。
- お客様の行動・初期データはダミー。実運用では IoT/PMS/位置測位などと連携する想定。
- 認証・権限管理は未実装。
